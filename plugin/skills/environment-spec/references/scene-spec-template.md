# Шаблон спецификации сцены или объекта

Таблицы ниже вставляются в раздел «Спецификация» файла роли (вид файла — `docs/CONVENTIONS.md`, раздел 6). Для одного объекта достаточно таблиц 1–4 и 8. Примеры в таблицах взяты из снимка канона версии 760: они показывают, как выглядит строка, а не готовое решение. Клетки с `…` заполняет автор.

Обозначения в клетках:

- `[canon:…]` — значение переписано из открытого файла канона.
- `[предложено]` — значение придумано автором; оно обязано попасть в таблицу «Новое (предложено)».
- «не снято в Studio» — значения нет в каноне, оно есть только на карте; строка добавляется в таблицу 1.
- «в каноне не указано» — канон молчит, а придумывать нельзя или незачем; если без значения строить нельзя, это открытый вопрос.

Правила строки:

- `Hero` принимает только значения Nail, Flint, Spark, Rue, Echo или пусто. [canon:lore-bible.md#ТЗ окружения для команды разработки] Какое значение у конкретной точки, таблица точек прямо не пишет: для точки героя оно следует из её имени, для остальных ставится «в каноне не указано».
- Колонка «Свет» у большинства объектов — «нет». Свет появляется, только если он есть в таблице 4.
- Статус: `модель` (строится на этом шаге), `маркер` (только прозрачная `Part` с атрибутами), `существует` (уже стоит, шаг его не трогает или дополняет — написать, что именно).

Цвет-якорь героя канон называет словом («ржавый коричневый»), а не числом. [canon:lore-bible.md#Облик героев] Значение `Color3.fromRGB` для него — `[предложено]`. Если число взято из файла арт-директора шага, рядом ставится `[draft:…]`; если из арт-библии — `[bible:…, предложено]`. Метка `[предложено]` снимается только тогда, когда значение принято владельцем в плане.

## 6. Проходка

Что игрок видит и проходит. Расстояние по горизонтали: √(Δx² + Δz²), округление до 0,1. Автор считает; исполнитель подтверждает снимком или выводом скрипта.
