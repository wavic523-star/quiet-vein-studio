# Настройка студии

Четыре шага. Первые два делает владелец, остальное — дирижёр в чате.

## 1. Установить плагин

Плагин `qv-studio` приходит файлом в чате. На карточке файла можно просмотреть содержимое и принять плагин кнопкой. После этого навыки плагина доступны в сессиях; роли-агенты загружаются там, где среда поддерживает агентов плагинов.

Если роли не появились как отдельные типы агентов, оркестр всё равно работает: дирижёр запускает обычного агента и даёт ему файл роли из `plugin/agents/`. На этом пути у роли остаются все инструменты сессии, поэтому дирижёр добавляет в запрос блок ограничений и после возврата сверяет изменённые пути (навык `orchestra`, раздел «Границы записи»). Что получилось на самом деле, покажет канарейка (шаг 4).

## 2. Создать репозиторий

1. На GitHub создать закрытый репозиторий `quiet-vein-studio` с файлом README. Облачная сессия работает только с уже существующим репозиторием.
2. Дать приложению Claude GitHub App доступ к этому репозиторию. Без него сессия может клонировать публичные репозитории, но не может работать в закрытом.
3. Написать в чат: «подключи <ваш логин>/quiet-vein-studio».

Справка: [Get started with Claude Code in the cloud](https://code.claude.com/docs/en/web-quickstart), раздел Connect GitHub.

## 3. Первый коммит

Дирижёр подключает репозиторий, кладёт в него это дерево первым коммитом и сообщает ссылку. С этого момента промежуточные результаты живут здесь.

По желанию: включить на GitHub защиту основной ветки, чтобы всё попадало в неё только через запрос на слияние. Сессии по умолчанию работают в ветках с приставкой `claude/`.

## 4. Канарейка

Короткая проверка до первого настоящего шага. Состояние на 16 ноября 2026 (версия плагина 0.1.2, до установки плагина и подключения репозитория):

| Что проверяем | Как | Результат |
| --- | --- | --- |
| Навыки плагина видны | Попросить «запусти оркестр: проверка» | не проверено: плагин ещё не установлен |
| Роли видны как типы агентов | Дирижёр смотрит список доступных агентов | не проверено: плагин ещё не установлен |
| Запасной путь по файлам ролей | Обычный агент читает `plugin/agents/<роль>.md` и работает как роль | работает: `environment-designer`, `continuity-reviewer` и `producer` прошли так пробный шаг и тесты |
| Запись в репозиторий | Тестовый коммит в ветку `claude/canary` и запрос на слияние | не проверено: репозитория на GitHub ещё нет; локальные коммиты работают |
| Роли не видят Studio и план | У агента роли нет этих инструментов в списке | **на запасном пути не выполняется**: обычный агент получает все инструменты сессии. В прогонах роли писали только в свои файлы, но держал их текст запрета, а не список инструментов |

Дирижёр обновляет таблицу после установки плагина и подключения репозитория.

## Что проверено

Прогоны 16 ноября 2026 в облачной сессии, на локальной копии репозитория.

**Тесты трёх основных навыков** (`tests/skills/`, по одному случаю, с навыком и без). Все утверждения прошли в обоих вариантах: 8 из 8, 8 из 8, 6 из 6. Разницы в счёте нет, то есть тесты пока слишком лёгкие: без плагина агент находит те же нарушения по `docs/CONVENTIONS.md` и снимку канона. Разница видна в другом: с навыком вердикт и решение идут в заданном формате, продюсер выносит владельцу все три критичных пункта, а без навыка сам отклоняет два из них и выдумывает свои классы решений; дирижёр без навыка зовёт лишнюю роль и правит `BACKLOG.md`. Вывод: основную защиту от выдумок даёт сам репозиторий (соглашения и снимок), навыки дают порядок и границы решений.

**Пробный шаг** `drafts/2026-11-16-dryrun-camp-mark/`: роль окружения, затем контролёр. Итог и время — в `ARCHIVED.md` этой папки. Возврат роли, продюсер и пакет для плана не запускались.

Повторная проверка версии 0.1.1 другим свежим агентом: блокеры закрыты все; из 26 замечаний исправлено 18, частично 7, не исправлено 1; найдено 15 новых (4 важных, блокеров нет). В версии 0.1.2 правки внесены по всем 15, но третьей проверки не было.

Что остаётся открытым после 0.1.2 (задача Б-6 в `BACKLOG.md`):

- действует ли список `tools` у ролей, запущенных как агенты плагина: проверяется только после установки;

## Позже

- **Каталог плагинов из репозитория.** Репозиторий уже размечен как каталог одного плагина (`.claude-plugin/marketplace.json`). Если подключить его как каталог, правки ролей будут доходить до сессий из репозитория. Справка: [Use plugins in Claude](https://support.claude.com/en/articles/13837440-use-plugins-in-claude).
- **Репозиторий в проекте.** Если добавить репозиторий в проект, его `CLAUDE.md` будет загружаться в сессиях проекта. Навыки и роли из папок репозитория в таких сессиях не загружаются, поэтому они и поставляются плагином. Справка: [Projects](https://code.claude.com/docs/en/claude-projects).
- **Настоящий форк чужого репозитория.** Нужен только если мы собираемся отправлять правки автору или следить за его обновлениями. Форк в ваш аккаунт делаете вы; для работы студии достаточно закреплённой копии в `third_party/`.

## Обновление снимка канона

Когда план изменился:

1. Выгрузить план в markdown средствами Claude Docs в файл `plan.md`.
2. Выполнить `python3 tools/canon_snapshot.py plan.md <версия плана> "<дата выгрузки>"`.
3. Закоммитить отдельным коммитом «Снимок канона, версия <N>».

Руками файлы в `canon/` не правятся.
