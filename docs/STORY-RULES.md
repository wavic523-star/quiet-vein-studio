# Правила репозитория для чата «Сюжет»

Составлено 16 ноября 2026 по словам владельца `[владелец:О-12]`–`[владелец:О-17]`. Порядок работы оркестра по сюжету — в `docs/STORY-ORCHESTRA.md`. Правки, которые нужны в инструкции проекта, — в `docs/INSTRUCTION-CHANGES.md`.

Старшинство: прямые слова владельца в чате → инструкция проекта → `CLAUDE.md` и этот файл → `docs/CONVENTIONS.md` → навыки плагина. Где этот файл уточняет навык плагина для работы чата «Сюжет», действует этот файл. Метки источников и ворота G1–G8 из `docs/CONVENTIONS.md` он не ослабляет.

## 1. Назначение

Чат «Сюжет» пишет полный сюжет игры по обновлениям, события, квесты одиночные и с друзьями, диалоги, а также оформление того, что видит и слышит игрок: сцены, облики, эффекты, музыку `[владелец:О-16]`. Порядок: сначала сюжет, затем сроки и шаги его синхронизации с функционалом игры по датам этапов плана и обновлений `[владелец:О-17]`. Основа — лор-библия плана `[владелец:О-15]`.

Репозиторий — мастерская чата. Канон игры остаётся в плане: в план попадает только то, что владелец принял подсказкой `[canon:step-order-agents.md#Порядок шага и агенты]`. Раздел плана «Сюжет и часы» прямо говорит, что историю разрабатывают вне плана, а план хранит только решения `[canon:stages.md#Этап 2: MVP, 21–27 ноября]`.

## 2. Границы чата

| Что | Можно | Нельзя | Опора |
| --- | --- | --- | --- |

| План (Claude Doc) | Читать: `read` и `export` инструментов Claude Docs | Править, оставлять подсказки и комментарии, принимать подсказки | `[владелец:О-15]` |
| Roblox Studio | Ничего | Любой вызов, даже на чтение | `[владелец:О-13]` |
| Другие чаты проекта, документы проекта, память | Читать и использовать для задач сюжета | Писать туда; выдавать слова из других чатов за решение владельца, пока их нет в `decisions/OWNER.md` | `[владелец:О-15]` |
| GitHub | Только этот репозиторий и только задачи этого чата | Другие репозитории для записи, настройки репозитория, приложения и права | `[владелец:О-14]` |
| Сеть | Чтение документации Roblox и страниц для проверки фактов и лицензий | Загрузки в Roblox, платные сервисы | `docs/CONVENTIONS.md`, ворота G3 |

Инструменты Roblox Studio технически видны в сессии через приложение на компьютере владельца. Дирижёр их не загружает и не вызывает. Роль получает запрет в тексте запроса (порядок в навыке `orchestra`, раздел «Как звать роль»). Если вызов всё же случился, это пишется первой строкой отчёта владельцу.

## 3. Ветка и коммиты

- Единственная рабочая ветка — `claude/Сюжет` `[владелец:О-12]`. Шаги различаются папками `drafts/<ГГГГ-ММ-ДД>-<слово>/`, а не ветками. Это заменяет правило «один шаг — одна ветка» из навыка `orchestra` для этого репозитория.
- Два шага одновременно можно вести только если у них разные папки и ни один не меняет файлы другого. Стыки между шагами решает дирижёр, а не роли.
- В `main` всё уходит запросом на слияние по вехе (например, «Арка v1 принята», «Пакет окна А готов»). Сливает владелец.
- Один коммит — одно действие: бриф, черновик роли, проверка, решение продюсера, перенос в `bibles/`, слова владельца. Сообщение — одна строка по-русски: что сделано и какой шаг.
- После каждого законченного куска — отправка ветки на GitHub, чтобы обрыв сессии не стёр работу.
- Не коммитятся `node_modules`, файлы SoundFont, ключи, токены, файлы больше 2 МБ без решения владельца.

## 4. Что где лежит

| Путь | Что | Кто пишет |
| --- | --- | --- |
| `canon/` | Снимок плана | Только скрипт `tools/canon_snapshot.py`, отдельным коммитом |
| `drafts/<шаг>/` | Бриф, файлы ролей, проверка, решение продюсера, пакет для плана | По таблице «Кто что может» в `docs/CONVENTIONS.md` и в `docs/STORY-ORCHESTRA.md` |
| `bibles/story/arc.md` | Сквозная арка: акты, обновления, что каждое открывает | Дирижёр, после решения продюсера |
| `bibles/story/chapters/`, `bibles/story/events/`, `bibles/story/quests.md`, `bibles/story/cast.md` | Принятые главы, события, квесты, развитие героев | Дирижёр |
| `bibles/story/registers/` | Живые реестры: загадки, журнал обновлений, сайд-истории | Дирижёр |
| `bibles/story/sync-map.md` | Карта синхронизации сюжета с функционалом и сроками | Дирижёр |
| `bibles/` (остальное) | Арт-библия, звуковая библия, строки-кандидаты манифеста | Дирижёр |
| `decisions/OWNER.md` | Слова владельца, которых нет в плане | Дирижёр, только со слов владельца, отдельным коммитом |
| `decisions/ESCALATIONS.md` | Вопросы владельцу и его ответы | Продюсер — вопросы; дирижёр — ответы со слов владельца |
| `decisions/LOG.md` | Решения продюсера и счёт находок ролей | Продюсер, дирижёр |
| `docs/` | Правила | Дирижёр |
| `plugin/` | Навыки и роли | Дирижёр, отдельным коммитом с причиной |
| `BACKLOG.md` | Подзадачи и сроки | Дирижёр |

Папки `bibles/story/…` создаются, когда в них впервые переносится принятое. Пустых заготовок не держим.

## 5. Как сюжет становится каноном

Статусы из `docs/CONVENTIONS.md`, раздел 1, плюс один промежуточный для сюжета:

1. `черновик` — файл роли в папке шага.
2. `проверен` — APPROVE контролёра.
3. `принят в репозитории` — решение продюсера по классам А и Б; документ переезжает в `bibles/story/`, метки `[предложено]` сохраняются.
4. `выбран владельцем` — владелец ответил на развилку в чате; ответ записан в `decisions/ESCALATIONS.md` и даёт метку `[владелец:E-N]`. Это решение владельца, но ещё не канон плана.
5. `принято владельцем` — владелец принял подсказку в плане. Только это канон. Отметку в шапке документа ставит дирижёр отдельным коммитом.

Строить в Studio можно только статус 5. Это делает чат «План» обычным порядком плана, а не этот чат.

Пакет для плана (`drafts/<шаг>/plan-proposal.md`) готовит дирижёр по навыку `orchestra`. Пока владелец не решил иначе, пакет лежит в репозитории, а дирижёр сообщает о нём в чате; передаёт пакет в чат, который владеет разделом плана, сам владелец. Вопрос, как передавать пакеты удобнее, вынесен в `docs/INSTRUCTION-CHANGES.md`.

## 6. Начало и конец сессии

В начале:

1. `git pull` ветки `claude/Сюжет`; дерево чистое.
2. Версия снимка (`canon/SNAPSHOT.txt`) против `data.rev` плана: дешёвое чтение по навыку `qv-plan-reader`. Если изменились разделы «Лор-библия», этапы, «События и календарь», «Монетизация» или «Не делаем», — новый снимок скриптом, отдельным коммитом, до любых черновиков. Если изменения в других разделах, — одна строка в отчёте.
3. Прочитать `BACKLOG.md` (группа З), открытые вопросы в `decisions/ESCALATIONS.md`, последние записи `decisions/LOG.md`.
4. Если владелец в чате сказал новое, — сначала запись в `decisions/OWNER.md`.

В конце: статусы задач в `BACKLOG.md` с датой, коммит, отправка ветки, отчёт владельцу по виду из `docs/STORY-ORCHESTRA.md`.

## 7. Чего чат не делает

- Не правит план и не пишет в Roblox Studio.
- Не придумывает цены, состав магазина, шансы и схему сохранений. Не загружает ничего в Roblox. Не тратит деньги.
- Не фиксирует ответы на загадки, пока владелец не решил иначе (ворота G1).
- Не сдвигает даты этапов и окон плана. Сроки сюжета внутри студии предлагает, даты плана берёт из снимка.
- Не выдаёт решение продюсера или своё за слова владельца.
