## Как поставить

Выбери один путь. Не ставь одни и те же навыки двумя путями сразу: появятся дубли (`qv-plan-reader` в аккаунте и `quiet-vein:qv-plan-reader` из плагина).

### Путь 1. Карточки навыков в чате (быстрее всего, GitHub не нужен)
Каждый навык сохраняется кнопкой на карточке. Он попадает в аккаунт и доступен во всех чатах проекта, в Cowork и в Claude Code. Версий и истории правок нет.

### Путь 2. Плагин из ZIP (без GitHub, 2 минуты)
1. Claude → Customize → Plugins → Add → Upload plugin.
2. Выбери `quiet-vein-plugin.zip` (в архиве `.claude-plugin/plugin.json` лежит в корне).
3. Проверка: в новом чате спроси «какие у тебя навыки из плагинов?». Ответ должен содержать `qv-plan-reader` и `qv-big-task`.
4. Обновление: загрузи новый ZIP.

### Путь 3. Закрытый репозиторий как маркетплейс (версии, история, проверка)
Нужен, когда навыков станет больше трёх или захочется смотреть каждую правку. По плану проекта это вариант после запуска.

1. ЖДЁТ ЧЕЛОВЕКА: на github.com создать закрытый (Private) репозиторий `quiet-vein-toolkit`. Проверка: рядом с названием значок Private.
2. ЖДЁТ ЧЕЛОВЕКА: загрузить содержимое этой папки в корень репозитория. Через браузер: Add file → Upload files, перетащить папки целиком. Скрытые папки `.claude-plugin` и `.github` должны попасть в репозиторий; если не попали, создать файлы через Add file → Create new file, вписав путь с косой чертой в имя файла. Через git: `git init`, `git add .`, `git commit -m init`, `git remote add origin ...`, `git push -u origin main`. Проверка: на главной странице репозитория видны папки `.claude-plugin`, `plugins`, `tools`.
3. ЖДЁТ ЧЕЛОВЕКА: Claude → Customize → Plugins → Add → Add marketplace, ввести `ваш-логин/quiet-vein-toolkit`. Когда диалог попросит, подключить GitHub и дать приложению Claude GitHub App доступ к этому репозиторию. Проверка: в списке появился плагин `quiet-vein`.
4. Включить Sync automatically у маркетплейса (если кнопки нет, после каждой правки нажимать Check for updates).
5. Проверка: как в пути 2, шаг 3.

Как обновляются навыки: правка файла в репозитории, коммит, потом Check for updates (или автосинхронизация). В `plugin.json` и `marketplace.json` нет поля `version`, поэтому новая версия определяется по коммиту. Если обновления перестанут доходить, задай `version` в одном `plugin.json` и повышай на каждой правке: Claude Code держит кэш, пока строка версии не изменится ([документация](https://code.claude.com/docs/en/plugins/host-marketplace#release-a-new-version)).

## Облачные запуски и MCP
- Репозиторий не нужно присоединять к облачной сессии: плагин, поставленный в аккаунт, подтягивается в сессии Claude Code под тем же аккаунтом при следующем старте (`/reload-plugins`). Работает ли это в облачных и запланированных сессиях именно у вас, не проверено: проверить одним тестовым запуском, спросив «какие у тебя навыки из плагинов?».
- Облачная сессия не видит вашу Studio (мост к компьютеру работает только в привязанных к устройству сессиях). Облако годится для черновиков и проверок текстом, не для шагов в Studio.
- Сможет ли облачный запуск читать Claude Doc плана, не проверено.
- Дополнительные MCP не нужны: Claude Docs, Studio MCP и встроенный браузер уже закрывают план, Studio и Creator Dashboard. Каждый лишний сервер увеличивает набор инструментов в контексте.
- Агентов (`agents/`) в плагин не кладём: чат их игнорирует, а роли агентов лора, маркетинга и ревью по плану задаются в разделе «Порядок шага и агенты».
