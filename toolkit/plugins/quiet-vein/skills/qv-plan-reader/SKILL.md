# qv-plan-reader

Правила дешёвого чтения плана (Claude Doc PYAV7Z6Ak4zjBRFodgk38j). Они не заменяют план: при расхождении прав план. Нужны инструменты Claude Docs (`read`). Для чтения README и других документов проекта см. дорожку 2.

## Стоимость (замер ноябрь 2026, версия плана 760)
- План ≈ 149 тыс. знаков, ≈ 55 тыс. токенов (оценка, 2,7 знака на токен). Целиком не читать.
- `outline` ≈ 6 тыс. токенов и всё равно обрезан. Фразу «сначала оглавление» (инструкция проекта, «Запросы агентам» в плане) выполняет карта ниже: оглавление получено без вызова. `outline` вызывай, только если нужного раздела в карте нет.
- Цифры «≈ ток» в карте это размер текста плана, а не цена чтения. Диапазон блоков стоит дороже: в ответе блоки лежат в XML и ещё раз списком `selection`, плюс ≈ 1,5 тыс. знаков подсказок инструмента и до ≈ 270 слов служебного текста. Для обычного текста считай ×2–2,5 (видно по самим ответам). Таблицы («Позже», таблицы этапов) по замеру проверяющего агента заметно дороже: «Позже» вышло ≈ 20 тыс. токенов при ≈ 3,5 тыс. текста (оценка).
- Поиск по тексту (`search` с `text`) возвращает только абзацы с совпадением, без дубля: для точечного вопроса он в разы дешевле диапазона. Локальная копия (дорожка 1) почти ничего не стоит в контексте.
- Независимые чтения отправляй одним сообщением.
- Самые тяжёлые разделы по тексту: Лор-библия ≈ 14 тыс., Журнал ≈ 10 тыс., Рабочие планы ≈ 10 тыс., Решения ≈ 5 тыс. токенов.

## Общие параметры вызова
`container` {"kind":"project","id":"PYAV7Z6Ak4zjBRFodgk38j"}, `ref` {"object":"node","id":"f71242bf-8dac"}, `engine` "prose". Номера блоков пишутся с префиксом `m0dx7g53801.`, например `m0dx7g53801.17222`.

`read` отложенный инструмент: сначала ToolSearch `select:mcp__Claude_Docs__read`. Если клиент перечисляет навык `docs` и требует его перед первым вызовом Claude Docs: он короткий (≈ 1 тыс. знаков), загрузи один раз; к чтению плана он ничего не добавляет.

## Две дорожки до лестницы (дорожка 1 первая)
1. **Локальная копия плана** (по умолчанию, если есть оболочка: нужно больше одного блока или любая таблица). Один раз `export`: container как выше, `file` `f71242bf-8dac` (так выгружалось в замере; при ошибке возьми допустимое из ответа), `format` "markdown". Большой ответ клиент сам сохраняет в файл в /tmp, в контекст приходит путь. Файл это JSON-список; в элементе [1] поле `text` содержит JSON с `data.bytes_b64`. Декодируй (`python3 -I скрипт.py ВХОД ВЫХОД.md`), ничего не печатая:
```python
import json, base64, sys
raw = json.load(open(sys.argv[1], encoding="utf-8"))
payload, _ = json.JSONDecoder().raw_decode(raw[1]["text"])
open(sys.argv[2], "w", encoding="utf-8").write(base64.b64decode(payload["data"]["bytes_b64"]).decode("utf-8"))
print("rev", payload["rev"])
```
Скрипт печатает версию плана на момент выгрузки (`payload["rev"]`): запиши её рядом с копией.
Дальше `grep -n "^## "` и `sed -n` по заголовкам: раздел «Герои» ≈ 1 тыс. токенов вместо диапазона со служебным текстом. Если ответ пришёл прямо в контекст, а не файлом, дорожка не подходит: иди по лестнице. Копия это снимок: когда любое чтение покажет `data.rev` выше записанной версии, выгрузи заново (один вызов). Номеров блоков в копии нет.
2. **README и другие документы проекта.** Не читать целиком (README ≈ 15 тыс. токенов, оценка). `project_search` с узким запросом: фрагмент ≈ 1 тыс. токенов. Целиком читать, только если фрагментов не хватило.

## Лестница (иди сверху вниз, остановись, когда ответ есть)
1. **Диапазон** (без оболочки, один-два небольших блока без таблиц; иначе дорожка 1). payload `{"kind":"search","blocks":{"first":"m0dx7g53801.A","last":"m0dx7g53801.B"}}`. Блоки от A до B целиком, остальное свёрнуто. Порядок в документе не равен порядку номеров: бери пары из таблицы. Несколько диапазонов нужны сразу: все вызовы в одном сообщении. Если нужна одна фраза, поиск по тексту (п. 4) дешевле.
2. **Версия бесплатно.** Каждый ответ содержит `data.rev` (версия всего плана; атрибут `rev` у блока другой: с картой его не сравнивай, он нужен только как база `sinceRev` в сверке ниже). Отдельного вызова не нужно. `data.rev` равен 760: карта верна. Больше: один раз `{"kind":"view","sinceRev":760}`, отметь изменившиеся блоки и перечитай нужные; уже прочитанные диапазоны сверь с этим списком.
3. **Указатель «тема → блок»** (прежде чем искать по слову): цвет, палитра, облик героев → Облик героев и ТЗ окружения; координаты, PoiId → Карта точек; длина реплик, ключи строк → Правила текста; цены, товары → Монетизация; кто что пишет в план, роли агентов, запросы агентам → Порядок шага и агенты.
4. **Поиск.** Блока нет в таблице: `{"kind":"search","text":"узкая фраза","limit":10}`. Широкое слово («бирюзов», «Crystal») тянет тяжёлые блоки «Блокеры» и «Проверка» (400–700 слов каждый). Ответ неполный (`complete:false`): тот же payload с `"from":N` из `next.from`.
5. **Один блок или список:** `{"kind":"view","parentId":"<id>"}`. У заголовка вернётся только заголовок: раздел читай диапазоном.
6. Ошибка `bad_request` содержит список допустимых полей. Не угадывай вслепую.

## Сверка (начало шага или автозапуска): четыре вызова в трёх раундах
Проверено 16 ноября 2026 свежим агентом.
- Раунд 1, одним сообщением. a) Блокеры: `{"kind":"search","text":"Блокеры (обновлено","limit":1}` вернёт один абзац (≈ 400–500 слов), сейчас это блок 35763. b1) Число записей журнала: `{"kind":"search","text":"Версия плана перед записью","limit":1,"from":50}`: контент пуст (≈ 100 токенов), в `data.hits` число записей.
- Раунд 2. b2) Последняя запись: тот же payload с `"from":<hits>` и `limit` 1 (`from` считается с 1). Без раунда 1 `limit` 1 вернул бы самую старую запись зря.
- Раунд 3. c) Что изменилось после последней записи: `{"kind":"view","sinceRev":N}`, где N это атрибут `rev` абзаца этой записи (в xml ответа b2, например `rev='760'`), а не число из фразы «Версия плана перед записью». Так принято и в самом журнале: следующая запись сверяется «с версии» `rev` предыдущей. Число из фразы это версия до собственных правок записи: с ним `sinceRev` вернул бы заново и Блокеры, и саму запись (≈ 11 тыс. знаков, проверено). Ответ содержит `data.rev` и полный текст изменённых блоков; пустой, если чужих правок не было. Чужие правки в «Блокерах» и в таблице этапа видны тут же.
- Открытые подсказки этими вызовами не проверялись: как их читать, смотри guide topic.suggestions.
